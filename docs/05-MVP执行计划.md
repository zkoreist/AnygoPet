### W1-1 决策反转说明（2026-09-18）

**原计划剥离键鼠映射，理由是"阶段一不需要，越简单越好"。fork 之后这个前提不成立了。**

|          | 原判断                     | 实际情况                                                            |
| -------- | -------------------------- | ------------------------------------------------------------------- |
| 代码形态 | 以为要自己加，加之前先不加 | fork 的骨架**已经完整实现了**，功能可直接用                         |
| 剥离代价 | 以为只是"不写"             | 要改设置面板、模型加载逻辑、Rust 插件三层；且必须留代码给阶段二恢复 |
| 投产比   | 省事                       | **负收益**——花力气把能用的功能拆掉，再花力气装回来                  |

**结论：保留键鼠映射，把精力转到模型替换与品牌改造上。**

保留前的核查已完成，两项都干净：

- **版权无冲突**：键鼠映射由三个外部库构成——`rdev`（MIT）、`gilrs`（Apache-2.0）、
  `tauri-plugin-global-shortcut`（Tauri 官方），均为宽松许可，允许商用与再分发
- **完全不联网**：逐行读过 `core/device.rs` 与 `core/gamepad.rs`，均为本地输入监听后
  向前端 `emit`，无任何网络请求；全库唯一的联网行为是自动更新，与键鼠映射无关

> 仍须注意：全局键鼠监听有**杀软误报**风险，这正是发版建议走
> Microsoft Store + MSIX（微软免费签名）的原因之一。

## 6. 分工与协作方式（v2.0 更新）

> **v1.0 的这段结论已失效，保留原文在下方便于回溯。**

**当前工作机（2026-09-19 实测）的 git 通道是通的**，直连 GitHub 正常，
TCP 443 与 api.github.com 均通过。因此原先的"只能由 K 编码"限制**不存在**。

当前的协作边界：

| 事项                                      | 谁做                                                                     |
| ----------------------------------------- | ------------------------------------------------------------------------ |
| clone / 改代码 / 提交                     | **AI 可直接执行**（已实际完成 4 个提交）                                 |
| **推送（push）到公开仓库**                | 需要明确确认后执行——仓库是 public，改动立即对外可见                      |
| 装系统级环境（MSVC / Rust / Node / pnpm） | 用户在真实终端执行——涉及 UAC 提权，且 AI 的执行沙箱会干扰 npm 等网络操作 |
| 运行 GUI 应用做目视验证                   | 用户执行，AI 负责读取客观证据（进程树、窗口枚举、注册表、文件系统）      |
| 授权合规、发版范围、排期                  | **必须由用户拍板**，不代做决定                                           |

一条已验证的经验：**AI 的执行沙箱与用户的真实终端环境不同**（PATH、网络行为都有差异）。
凡是"在我这边跑通了"的结论，都要在用户终端复验一次才算数——
本项目已两次栽在这上面（一次找错 Node 位置，一次 npm 装包卡死）。

```bash
cd AnygoPet
pnpm install && pnpm tauri dev
```

⚠️ 换机必读 `docs/03` **第 7 节与第 10 节**：

- 第 7 节是通用坑（pnpm v11+ 的 `allowBuilds`、Node 装到非标准路径导致不在 PATH 上等）
