# 技术选型与架构决策

> 版本：v1.0 ｜ 日期：2026-09-18 ｜ 状态：已决策

## 1. 结论

**fork `ayangweb/BongoCat`（MIT 协议），沿用其 Tauri 2 + Vue 3 + TypeScript + PixiJS 8 技术栈。**

第一阶段剥离键位映射能力，替换为可合法再分发的原创形象，以开源项目的形式发布。

## 2. 决策依据

### 2.1 GitHub 现状调研（2026-09-18 实际核实）

| 项目 | 技术栈 | Star | 协议 | 最后提交 | 备注 |
|---|---|---|---|---|---|
| **ayangweb/BongoCat** | Tauri 2 + Vue 3 + PixiJS | **23,280** | MIT | 2026-09-17 | 本品类事实标准；配套 Awesome-BongoCat 模型生态（2,001⭐）+ 在线模型转换器 |

**关键发现：不存在成熟的「照片 → 桌宠」开源方案。** 中英文多轮检索均无结果，该功能需要自行拼装（详见 02 号文档阶段三）。

### 2.2 候选技术栈对比

| 方案 | 透明/置顶/穿透 | 全局键位（免管理员） | 常驻内存 | 打包体积 | 新手风险 |
|---|---|---|---|---|---|
| **Tauri 2** | 原生支持，`setIgnoreCursorEvents` | `tauri-plugin-global-shortcut` / rdev | 30–120MB | 3–30MB | 中（需 Rust 工具链） |
| Electron | `setIgnoreMouseEvents` 成熟 | 需 `uiohook-napi` | 120–450MB | 80–280MB | 低 |
| Python + PySide6 | 支持，但合成开销大、低端机掉帧 | `pynput` | 50–65MB | 45–118MB | 高（Qt 样式与打包） |
| Godot 4 | 支持，需手搓视口 | 需自写 GDExtension（C++） | 中等 | 20–30MB | 高 |
| C# WPF / WinUI3 | 支持，穿透需双窗口 | `SharpHook` | 50–120MB | 1–150MB | 高（需 P/Invoke） |

### 2.3 为什么最终选 Tauri 2

1. **有同级别参照实现。** 23k star 的活跃项目已经把透明窗、置顶、托盘、模型加载、键鼠监听全部跑通，所有坑都有现成解法可读。
2. **办公本友好。** 常驻 30–120MB、安装包 3–30MB，对比 Electron 的 120–450MB / 80–280MB，在无独显办公本上差距明显。
3. **第一阶段几乎不用写 Rust。** 因为第一阶段明确不做键位映射，唯一需要触碰原生的能力被推迟了，前端逻辑全在 Vue/TS 里。

**一次性代价：** 必须安装 MSVC 生成工具（C++ 桌面开发工作负载，约 5GB 磁盘）。这是本方案唯一的真实门槛。

## 3. 技术栈版本清单

来源：BongoCat 仓库 `package.json`（2026-09-18）

| 类别 | 组件 | 版本 |
|---|---|---|
| 运行时 | Node.js | 22 LTS |
| 包管理 | **pnpm**（强制） | 最新稳定版 |
| 原生 | Rust | stable（rustup） |
| 原生 | MSVC 生成工具 | C++ 桌面开发工作负载 |
| 壳 | Tauri | 2.10.x |
| 前端 | Vue | 3.5.x |
| 构建 | Vite | 6.4.x |
| 语言 | TypeScript | 5.9.x |
| **渲染** | **PixiJS** | **8.18.x（WebGL）** |
| 可选 | easy-live2d | 0.4.x |

**已启用的 Tauri 插件：** autostart、clipboard-manager、dialog、fs、global-shortcut、log、opener、os、process、updater。另有 `@tauri-store/pinia`（状态持久化）与 `vue-i18n`（多语言）。

> ⚠️ **渲染层是 PixiJS，不是普通 DOM。** 模型和动画都跑在 WebGL 画布上，团队需要掌握 PixiJS 的基础概念（Stage / Sprite / Texture / Ticker）。这一点会影响美术资源的组织方式和动画实现方式。

> ⚠️ **更正（2026-09-18）：角色本体是 Live2D 模型，不是序列帧。**
> 实际仓库结构为 `src-tauri/assets/models/{standard,keyboard,gamepad}/`，每套含 `cat.model3.json` + `.moc3` + 贴图；只有按键与桌面背景是普通 PNG，由 `easy-live2d` 在 Pixi 画布上渲染。
> **结论：换形象 = 换 Live2D 模型，需要绑骨（Cubism Editor），CC0 精灵素材不能直接套用。**
> 这是我早期判断错误导致的一处更正，后续方案以本条为准。

## 4. 架构分层

```
┌─ 交互层 ── 鼠标事件（点击 / 拖拽 / 悬停）· 行为状态机 · 右键菜单
├─ 表现层 ── 透明置顶窗口 · PixiJS 渲染 · 动画播放
├─ 资源层 ── 外观包：模型 · 贴图 · 动作 · config.json（换肤 = 换包）
├─ 系统层 ── 全局键鼠钩子 · 托盘 · 开机自启 · 单实例 · DPI 适配
└─ 扩展层 ── （后期）照片抠图 · 动作生成 · 用户模型库 · 分享导出
```

各层之间保持可替换：**换技术栈只会影响表现层与资源层**，交互层与系统层的逻辑可以复用。

## 5. 关键风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| MSVC 生成工具装不上 | 项目无法启动 | 优先验证，装不上就换 Electron 路线 |
| 全局键鼠钩子被杀软误报为键盘记录器 | 用户不敢装 | 阶段二引入监听时必须评估代码签名 |
| Bongo Cat 原形象版权 | 无法合法分发 / 商用 | **必须替换**。代码 MIT，美术不是（原画师 @StrayRogue，仅口头许可原网站） |
| 误用 `npm install` | 安装直接失败 | 项目 `preinstall` 强制 `only-allow pnpm` |
| 高 DPI 未处理 | 边缘发糊、拖拽坐标错位 | 第一版必须处理（办公本普遍 125%/150%） |
| 素材未纳入版本管理 | 换机即丢失 | 见 03 号文档 |

## 6. 被否决的方案及原因

- **Electron**：体积与内存翻倍，且本品类没有同量级的参照项目。若团队完全无法安装 Rust 工具链，则回退到此方案。
- **Godot 4**：透明窗可用，但全局键位需自写 GDExtension（C++），且与 Web 前端生态割裂，新手成本陡增。
- **Python + PySide6**：透明窗合成开销大、无硬件加速时掉帧，打包 45–118MB 且易误报，生态弱。
- **C# / VPet 路线**：生态完整（6.8k star、有 Mod 系统），但放弃跨平台，且团队无 C# 背景。

## 7. 待验证事项

第一次跑通源码后需逐项确认：

- [ ] MSVC 生成工具是否安装成功
- [ ] `pnpm install && pnpm tauri dev` 能否一次跑通
- [ ] 模型加载机制：从 Awesome-BongoCat 下载一个模型导入，确认目录结构与 JSON 配置字段
- [ ] 键鼠监听位于哪一层（阶段一需屏蔽，阶段二需恢复）
- [ ] PixiJS 在本机核显上的实际帧率与占用
- [ ] 高 DPI（125% / 150%）下的渲染清晰度与拖拽坐标是否准确
