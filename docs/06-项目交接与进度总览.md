## 1. 项目一句话

**AnygoPet** 是一款桌面宠物应用：用键盘、鼠标和手柄的实时操作驱动屏幕上的 Live2D 角色。
本项目 fork 自开源的 [BongoCat](https://github.com/ayangweb/BongoCat)（MIT），
**保留其键鼠/手柄映射能力**，把工作重心放在「替换原创形象 + 品牌改造 + 商业发布」上。

| 项       | 值                                                      |
| -------- | ------------------------------------------------------- |
| 仓库     | `github.com/zkoreist/AnygoPet`（public，master）        |
| 技术栈   | Tauri 2 + Vue 3 + TypeScript + PixiJS 8 + easy-live2d   |
| 角色形态 | Live2D `.moc3`（**不是**序列帧，**不是** 3D 模型）      |
| 包管理   | **强制 pnpm**（`preinstall` 有 `only-allow pnpm` 拦截） |
| 目标平台 | **Windows 优先**（无独显办公笔记本）                    |

## 3. 关键决策与理由

> 这一节是本文档**最重要的部分**。一个不知道来龙去脉的接手者，最容易在这里帮倒忙。

### 3.1 ✅ 保留键鼠映射（2026-09-18 决策**反转**）

**原计划**：阶段一不需要键鼠映射，把它剥离掉，让应用更简单。
**实际决定**：**保留**。

**为什么反转**：原判断建立在一个错误前提上 —— 以为「键鼠映射要自己写，所以先不写」。
但 fork 的是一个**已经完整实现了该功能**的应用，剥离反而要付出三重代价：

1. 要改动设置面板、模型加载逻辑、Rust 插件三层
2. 必须留有恢复路径给阶段二，等于留一堆「残骸代码」
3. 把能用的功能拆掉再装回来，**纯负收益**

**保留前的核查结论**（两项都干净）：

- **版权无冲突**：由 `rdev`（MIT）、`gilrs`（Apache-2.0）、`tauri-plugin-global-shortcut`（Tauri 官方）三个宽松许可库构成
- **完全不联网**：逐行核查过 `core/device.rs` 与 `core/gamepad.rs`，都是「本地监听 → 向前端 emit」，无任何网络请求

**遗留注意**：全局键鼠监听有**杀软误报**风险 → 这是发版走 Microsoft Store + MSIX 的原因之一。

### 3.2 ✅ 模型页保留上游资源入口（2026-09-19）

模型设置页有三个浮动按钮（制作教程 / 在线转换工具 / 模型库），都指向上游社区资源。

**决定：保留，但在 UI 提示里标注「上游」来源**，不做自营替换。
理由：移除会让用户完全没有获取/制作模型的入口，而自建服务成本高且非当前目标。

### 3.3 ✅ 应用标识统一为 `com.anygo.pet`

**踩过的坑**：Tauri 的**平台配置文件会覆盖主配置**。
`tauri.windows.conf.json` 等三处原本还写着上游的 `com.ayangweb.BongoCat`，
导致「主配置改了名」但「Windows 实际产物没改名」。

**接手提醒**：**改 identifier / productName 这类全局字段时，必须同时检查
`tauri.windows.conf.json`、`tauri.macos.conf.json`、`tauri.linux.conf.json` 三个文件。**

### 3.4 ✅ 更新走自有签名密钥

- 密钥对 keyid：`3AC97C02EAB1DA9F`
- 🔴 **私钥位置**：`C:\Users\Administrator\.tauri\anygo-pet.key`（**在项目目录之外、未入库**）
- 🔴 **丢失后果**：**永久无法签发应用更新包**，已安装用户会永远卡在旧版本
- **接手第一件事：确认用户是否已备份该私钥。**
- CI 需要配置的 secrets：`TAURI_SIGNING_PRIVATE_KEY`、`TAURI_SIGNING_PRIVATE_KEY_PASSWORD`、`RELEASE_TOKEN`

### 3.5 ✅ 商用走 Microsoft Store + MSIX

微软提供**免费代码签名**，可规避杀软对全局键鼠监听的误报。详见 `docs/04`。

## 4. 硬约束与实测数据

| 指标         | 约束         | 实测                                        | 状态                        |
| ------------ | ------------ | ------------------------------------------- | --------------------------- |
| 安装包体积   | ≤ 30 MB      | **5.15 MB**                                 | ✅ 只用 17%                 |
| **常驻内存** | ≤ 120 MB     | 工作集 **650.8 MB** / 私有内存 **426.4 MB** | 🔴 **严重超标，待重新定标** |
| 冷启动       | ≤ 2 s        | **未实测**                                  | ⬜                          |
| 目标机器     | 无独显办公本 | 渲染依赖 WebGL                              | —                           |

### 内存这条为什么需要重新定标（重要）

**测量方法**：按进程树精确归属，只统计 AnygoPet 及其派生进程，**排除**了机器上
其他应用共用的 WebView2 进程（全机 22 个 `msedgewebview2.exe`，属于本应用的只有 8 个）。

| 口径                 | 主进程  | WebView2 派生 ×8 | 合计         |
| -------------------- | ------- | ---------------- | ------------ |
| 工作集（逐进程相加） | 77.2 MB | 573.6 MB         | **650.8 MB** |
| 私有内存（扣除共享） | 45.2 MB | 381.2 MB         | **426.4 MB** |

- 工作集口径会**重复计入各进程映射的共享代码页**（Chromium 多进程架构的通病），对 WebView2 偏不公
- **但两种口径都远超 120MB**
- **结论：120MB 这个指标对 WebView2 方案不现实。** 参考：dev 模式下是 984.6MB，
  发布构建已降到 650.8MB，说明优化空间有限 —— WebView2 多进程架构有**固定内存地板**

**需要的动作：拿这组数字与产品侧重新约定指标。**建议改用「私有内存」口径定标
（更公允，且不会因共享库而虚高）。**这件事比模型替换更早影响架构决策。**

## 6. 待拍板的问题

### 6.1 图标图源方案

**背景**：当前图标仍由上游素材 `src-tauri/assets/logo.png` 生成。
已实测：**内置 AI 图像生成产出带水印，且「透明背景」是画上去的棋盘格（不是真 alpha）**，
不适合做商业品牌资产。

| 方案                          | 权利清晰度 | 说明                      |
| ----------------------------- | ---------- | ------------------------- |
| **A. 设计师按方向稿出矢量版** | ✅ 最清晰  | **推荐**。托盘版一起出    |
| B. 商用条款明确的 AI 渠道     | ⚠️ 需核对  | 必须确认条款 + 产出无水印 |
| C. CC0 图标素材               | ✅ 清晰    | 现成可用，但品牌辨识度弱  |

**一条已实测的设计结论**：按 64/48/32/24/16 五档对比缩放，
**全身版在 32px 以下糊成一团，而「仅头部」简化版在 32px 仍能认出是猫脸**。
→ **托盘图标（16–24px）必须单独出一版只留头的**，否则任务栏上就是一坨橙色。

### 6.2 角色模型方案

**先说清一个硬边界：AI 无法产出可用的 Live2D 模型。**

`moc3` 不是一张图，而是三层结构：

1. **立绘**（拆好图层的 PSD）← AI 能出这一层
2. **网格与变形器**（mesh / deformer）← **必须人工在 Live2D Cubism Editor 里做**
3. **参数绑定**（parameters）← **同样必须人工做**

第 2、3 层才是 Live2D 的核心工作量。而且第 1 层还必须是**拆好图层**的，
AI 出的是合并图层的成品图，**根本没法拿去绑定**。

| 方案                                | 成本量级       | 说明                                     |
| ----------------------------------- | -------------- | ---------------------------------------- |
| **A. 采购可商用 Live2D 成品**       | ¥350–1400      | **最现实**：授权明确、见效快、不阻塞 MVP |
| B. 委托「画师 + Live2D 绑定师」定制 | 需询价，周期长 | 权利最干净，可完全贴合品牌               |
| C. 找 CC0 / CC-BY 模型              | 0              | 免费，但风格契合度难保证                 |

**现状**：开发期可继续沿用上游模型（`docs/05` 已记录此约定），
**但 v1.0 发布前必须替换。**
